> 主题那条的核查过程值得记：一开始数出「73 处硬编码」，看着像漏网之鱼。
> 逐个看下来**三处都是合法用途**——尤其 `ImmersiveChrome` 看似硬编码，

### 无障碍覆盖实测（本轮补做，发现并修掉一个真缺口）

目标 ④ 要求「无障碍……**全量覆盖**」。本轮**第一次量化**了它：

- 全仓 **82 个可交互组件**
- **74 个**有可访问名称（Button 的构造参数即标签、输入框有 placeholder）→ 90%
- **5 个 `Toggle` 完全没有** —— 它们是裸开关，自身无文本，旁边那行 `Text` 标签
  **不会**自动关联，读屏只会念「开关」

**已修**：5 个 `Toggle` 全部挂上 `accessibilityText`（其中 `uuid-password` 的
`buildSwitchRow` 是共享 `@Builder`，用它的 `label` 参数一次覆盖所有调用点）。

**已加门禁**：`check-pages.mjs` §6 —— 任何 `Toggle`/`Checkbox`/`Radio` 没有
`.accessibilityText` 即判失败，并已纳入变异验证。

> ⚠️ 修的时候**又一次验证了第十道门禁的价值**：`.accessibilityText($r('app.string.x'))`
> 传的是 `Resource` 而该 API 要 `string`，**九道 Node 门禁全绿**，
> 只有真编译报 `No overload matches this call`。正确写法是
> `.accessibilityText(ToolUiKit.text($r('app.string.x')))`。

## 五、需要开发者决策的 5 件事（**代码侧已无排队工作**）

### 1. 真机回归（**不能省**）

十道门禁**覆盖不到**契约、资源引用、权限与生命周期。已实测出**三个编译期完全不可见**的缺陷：

- 返回键无反应（`router.back()` 在 NavPathStack 体系下失效）
- `onPageShow` 失活（`NavDestination` 弹出时不触发）
- HdsTabs 页签一个都不渲染（框架组件把配置项声明成 `private`，只给一行 WARN）

**最小核对清单**：
从工具页返回 → 返回后页签状态 → 返回后「最近使用」是否更新 → 关于页入口 →
**首页页签是否真的显示** → 深色模式 → 大字体（关怀模式四档）→ 超长/非法输入不崩 →
平板/2in1 网格列数。

### 2. 配色口径

框架调色板（`#0B57D0` + 玻璃拟态）与本 App 的蓝（`#0962F2`）**目前同屏并存**：
沉浸式底板用框架色、下面的工具网格用工具箱色。需要定一套。

### 3. `TOP_SAFE_INSET = 28` 需真机校准

取自框架注释、在**另一台设备**上实测的值。本机顶部避让是否合适要看真机。

### 4. 剪贴板粘贴按钮是否恢复

原按钮需要 `ohos.permission.READ_PASTEBOARD`，与「权限仅 INTERNET」红线冲突，
已**移除**并在代码里留了恢复说明。要恢复就得先确认放宽权限。

### 5. 提交前清理签名材料

`build-profile.json5` 被 git 跟踪，DevEco 自动签名会把 `storePassword`/`keyPassword`
写进去。**`HEAD` 版本是干净的**，但当前工作树含签名材料 —— 一次 `git add .` 就会提交上去。
CI 侧有 `strip_signing.py` 兜底，但**管不到本地提交**。

> 另：版本号仍是 `0.1.0`，是否升版由开发者决定。
