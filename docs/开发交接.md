## 二、刻意没做（等开发阶段）

1. **NGF 正式接线**：EntryAbility 尚未调 `ngfStarterKernel.bootstrap()` 等框架初始化。接线范式直接参考 airwavefootprints 仓 `entry/src/main/ets/entryability/EntryAbility.ets` 与其 `GlobalContext` 写法：bindAbilityContext → bootstrap → 主题/i18n/窗口门面初始化。接线时同步建立工具箱自己的 GlobalContext。
2. **工具注册表与正式首页**：搜索 + 收藏 + 工具网格未实现；Index 只是占位。注册表设计要点见产品定义稿 §四。
3. **16 件工具本体**：一件未实现。按产品定义稿 §六 M2 分三批落地，每批过真机回归再进下一批；每件工具的纯逻辑先行并同行单元测试。
4. **本地签名**：仓库不含签名材料；首次用 DevEco 打开时配置自动签名即可本地调试。
5. **发布签名 Secrets**：sign-and-release 需要在 GitHub 仓库 Secrets 配置签名材料后才会真正签名（无 Secrets 时按工作流既有逻辑跳过、不报错），上架前由开发者配置。
6. **反馈中心 app_id**：上架前在反馈中心后端 apps.py 注册 `ngftoolbox` 并把反馈入口接进「关于」页（脚手架阶段未接）。
7. **框架仓 README 快速开始**：在 NGF 来源仓补「如何引入 HAR + 最小示例」，与本仓 README 互链（样板推广回路，见产品定义的上位简报）。

## 三、建议开发顺序

1. NGF 接线 + 工具注册表 + 正式首页骨架（含收藏/最近使用，data 层落盘）。
2. 第一批工具（纯逻辑四件）：正则测试、JSON 工具、时间戳、编解码套件。
3. 第二批：摘要计算、JWT 解码、Cron 解析、进制转换、日期计算、UUID 与随机密码。
4. 第三批：二维码生成、代码查看、端口测试、子网计算、颜色转换、文本 Diff。
5. 关于页（NGF 专区：框架介绍/仓库二维码/同框架作品/反馈入口）+ 双语双主题收尾。
6. 商店物料（正式图标、截图、简介）→ 提审 → 开源发布动作（仓库已公开则同步 Release）→ 社区发布帖。
