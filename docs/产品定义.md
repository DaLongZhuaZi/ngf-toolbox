## 一、产品定位

**一句话**：给鸿蒙开发者和极客的离线微工具聚合——一个箱子装下十个每天用得着的小工具，同时是 NGF 框架的官方样板应用。

- **目标用户**：鸿蒙开发者、自托管/VPS 玩家、IT 从业者（与 A′/H 的人群同带，可交叉导流）。
- **赛道位置**（2026-10-16 NEXT 实查）：所覆盖的微赛道全线冷门——正则类头部 902 次、代码编辑器头部 4,309 次、端口扫描按名 0 条。单品天花板低，聚合后的人群价值远大于单品之和。
- **差异化三条**：① 全离线、零遥测、默认无网络权限（端口测试单项除外，使用时明示）——延续电波足迹的信任招牌；② 工具可扩展架构（注册表式，本身就是框架卖点）；③ 开源样板，代码即文档。
- **完全免费（已定 2026-10-16）**：样板与推广资产定位，免费全功能、无内购、无广告；收益记在框架引流与品牌上。
- **工具数量策略（已定 2026-10-16）**：尽可能多——首发批扩到 16 件，后续按月持续追加，目标 30+；靠注册表架构把单件边际成本压到最低（纯逻辑工具每件约 0.5–1 天含测试）。数量不让步质量门禁：每件仍须完整、带单测、过真机回归才上架（样板定位下，一件烂工具的广告效果是负的）。

### 3.2 持续追加池（上线后按月 2–4 件追加，目标总量 30+）

XML 格式化、SQL 格式化、条形码生成、HTTP 状态码/方法速查、UA 解析、单位换算（长度/面积/数据量）、数据量换算、ASCII 速查表、chmod 权限计算、JSON↔CSV 互转、字数统计组（字数/行数/去重行/行排序）、代码编辑（在查看器上加）、农历换算。追加顺序由反馈中心与 QQ 群呼声决定（E 案周报同款方法）。

**明确不做**：任何需要联网接口的工具（IP 查询、Whois 等——违 F1 且官网实查该类已被查询类应用挤占）、AI 类工具、需要账号的功能。

## 四、信息架构与统一交互

- **首页**：搜索框 + 收藏区 + 工具网格（图标+名称+一句话）；工具超过 12 个后加分类（编解码/文本/网络/文件）。
- **工具页统一模板**：输入区 → 一键处理（或实时处理）→ 输出区 → [复制] [存入历史] [清空]；输入自动保存草稿（data 层），杀进程不丢。
- **统一规范**：输出一键复制且复制后 toast 提示；错误就地红字说明（JSON/正则的错误定位到位置）；全部工具支持深色；大字体不溢出（沿 AF 的适配纪律）。
- **权限**：默认零权限；文件类走系统选择器（不申请存储权限）；仅端口测试需要网络，使用页内明示「本工具会连接你输入的主机」。

## 五、样板仓要求（开源侧定义）

- 仓库结构即教学：每个工具一个独立模块，模块 README 一段话说明它用了哪层 NGF、入口在哪；根 README 放映射总表（复用第三节表格）。
- 代码注释密度向「给陌生开发者看」看齐，关键样板点（工具注册、主题切换、数据持久化）写清为什么这样分层。
- 沿用 af 仓的 CI（harmonyos-ci 镜像 + 标签签名发布）与代码规范；单元测试覆盖全部纯逻辑工具（正则/编解码/摘要/时间戳必须 100% 有测试——这是样板的可信度来源）。
- Issue 模板区分「工具箱产品问题」与「框架使用问题」，后者引导到框架仓（简报 05 的支持边界）。

## 七、质量门禁（样板定位追加）

- 崩溃零容忍：上架前全工具真机回归一遍（含大文件、超长输入、非法输入 fuzz 抽测）。
- 评分目标 4.5+ 才启动社区推广动作（简报 05 已定）；低于目标先修产品不发帖。
- 每个工具一句「做不到什么」写进帮助区（如正则不支持回溯引用外的引擎差异），诚实边界延续 AF 风格。
